# Search — Web Browser

A fast, clean, privacy-minded Android web browser. Built by MEBS (Mohameds Engineering and Build Studio).

- **Package:** `com.devbangs.search`
- **Current version:** see `versionCode` / `versionName` in `app/build.gradle.kts`
- **Min SDK:** 24 (Android 7.0) · **Target/Compile SDK:** 36

---

## What it is

Search is a lightweight WebView-based browser focused on a clean home page, built-in ad blocking, and a fast, uncluttered experience. It pairs a native Android shell (toolbar, tabs, settings, downloads) with a web-based home page (`home.html`) that hosts the omnibox, quick-access tiles, and a news feed.

## Features

- **Clean home page** — omnibox search, quick-access tiles (YouTube, Facebook, ChatGPT, Wikipedia), voice search, and QR scanning.
- **Bars** — both bars are square, one shape on every page: the top bar (`TopSheetBar`) and the bottom bar (`NavSheetView`, whose only curve is the arc round the New tab button) meet the page with a straight edge, a hairline and a soft shadow. Neither covers any of a website: the page starts below the top bar and, on a website, stops at the bottom bar's straight edge.
- **Home page scrolled** — once home's own search box scrolls away, the same box takes the top bar on its own: the owl and the gear slide away, the box keeps home's colour with no outline and home's 16dp from either edge, 44dp tall and centred in the bar with 7dp above and below as Chrome's is, and the bar fades into the page's background, its line and shadow with it (`TopSheetBar.blend`, driven by `setHomeBarProgress`). Scrolling back up brings the owl and the gear back.
- **Search mode** — laid out as Chrome's: the search field and the suggestions are two cards of the same colour (`sugSheet`), the field with no outline, on the search page's own background (`searchPageBg`; Night Owl's wash in Night Owl), and the top bar goes flat in that background (`TopSheetBar.flat` - no curve, shadow or line).
- **Bottom bar** — Home, Bookmarks, a round Search button sitting in an arc of the bar's top edge - the Search owl peeking up into a sky that follows the phone's clock (`OwlButtonView`: a blue sky, the sun and drifting clouds by day; an orange horizon with the sun sinking behind the owl from 18:15; stars, a shooting star now and then and the moon in its real phase from 19:15, and the reverse at dawn; the owl is alive - see The owl below; Night Owl tabs always show the night; it animates only while on screen - 30fps for half a minute after it appears or is tapped, 15fps after that, 8fps in Battery Saver - and holds still when animations are off); a tap opens search in the tab on screen, exactly as a tap on the search box does, with no new tab - (`NavSheetView` draws the bar, its arc, the ring around the button and the shadow as one shape), Tabs (with the open-tab count on a badge) and Menu, icons only, with tooltips on long press; long-pressing Tabs also opens a new tab. Back, Forward and Reload are the first row of the menu, and Settings is the gear at the top right. While a page loads, a ring fills around the New tab button in a gradient of the chosen accent (`LoadRingView`); there is no line across the top of the page. The bar is a 56dp row of buttons. On the home page the page runs 28dp on under the bar, as its bottom padding and the feed's ad card allow for; on a website it stops at the bar's straight edge (`applyBarOverlap`), so nothing a site pins to the bottom of its window is hidden under the bar - only the New tab button floats over its centre. Scrolling down a page - the home page or a website - slides both bars away and gives the page the whole screen; scrolling up, reaching the top, a new page, a tab switch, search, the menu or the tab deck bring them back (Settings → Customize → Hide bars while scrolling, on by default; never with TalkBack on). The page takes the whole screen at the start of a hide, while the bars still cover its new edges, and gives it back at the end of a show, behind the bar - each time offset in the same frame so its text does not jump - and the bars slide under the status and navigation bar strips, which keep the bars' colours meanwhile (`EdgeScrim`), so no white shows during either move. Pages are never told a system bar overlaps them (no false `env(safe-area-inset-*)`), so a site's own bottom bar, such as YouTube's, sits flush against ours. A sideways swipe across the bottom bar (`SwipeBar`) moves between tabs, the page following the finger with the next tab sliding in beside it; a flick or a third of the way carries through, past the first or last tab it only gives like rubber. Gestures finish on a small damped spring (`Spring.kt`) that carries the finger's speed. The bar steps aside while typing into a page, and the page shrinks above the keyboard so the field being typed in stays visible.
- **Site icon in search** — searching from a website shows that site's own icon, crisp, at the start of the search field (`SiteIcons`): the page is asked which icons it declares (apple-touch-icon and icons with a declared size), the smallest of at least 96px is taken, with /apple-touch-icon.png and /favicon.ico on the site itself as fallbacks - no third-party icon service, so nobody but the site learns where the user is. Kept in memory and in the cache directory (memory only in Night Owl).
- **Page colours in the bars** (off by default) — when turned on in Settings → Customize → Page colours in the bars, both bars take one steady colour per site, as Chrome's toolbar does: the site's `theme-color` when it names one, otherwise the top of the page (`PageTint`, calmed to 40% saturation; dark bars get light text and icons). The address box sits on a solid pane worked out from the bar's colour - a shade darker on a light bar, lighter on a dark one - and eases with it (`fieldPane`), so it never disappears into the bar. Never on the home page, in Night Owl or on error pages.
- **Page tools** (Menu) — Share…, Translate page (Google Translate's page proxy, in the phone's language; "Show original" on a translated page), Reader view (the article alone in clean type, built in the page itself - `ReaderView`; run again to bring the site back), Add to Home screen (the page as its own icon - `HomeShortcut`), and Reopen closed tab.
- **On the home screen** — long-press the app icon for New tab, Night Owl tab, Voice search and Scan QR (`shortcuts.xml`); a resizable Search widget (owl, search pill, mic and QR, `SearchWidget`), offered from Settings → Add the Search widget where the launcher supports pinning; a Night Owl Quick Settings tile (`OwlTileService`); and "Search" in the text-selection menu of every app (`ProcessTextActivity`, PROCESS_TEXT).
- **Jump back in** — home shows the page last read in another tab, and a tap returns to that very tab with its history. Coming back after four hours or more opens on home, so the fresh Top Stories are what you meet (Settings → Customize → Open home after 4 hours away; the old tab is kept, never navigated). Home's shortcut tiles are the sites used most, scored by frecency with a two-week half-life (`SiteVisits`), so one visit to somewhere new no longer pushes a daily favourite off.
- **Privacy stats** — while ad blocking is on, home says how many ads and trackers were blocked this week and about how much data that saved (`PrivacyStats`, counted on the phone, never sent). Blocking matches by walking the host's suffixes against a set, so a request costs a handful of lookups rather than a scan of the list; toolsepulse.co is never blocked.
- **Smarter long-press** — on a link: Open in new tab (in the background, with "Switch" on a snackbar), Open in Night Owl tab, Copy link text, Download link; on an image, Search image with Google Lens. On the address: Copy link, Share, Paste and go, Edit. Held Back or Forward in the menu lists the tab's pages that way, to jump straight to one.
- **Page info** — tap the site's icon in the address box: whether the connection is secure and who issued the certificate, what the site has been allowed (location, camera and microphone, with Reset permissions) and whether its ads are blocked, with Block ads / Allow ads right there.
- **Tab tools** — the deck has a filter box (by title or address), drag to reorder, and an overflow with Close all tabs, Close other tabs, Close duplicate tabs (n), Reopen closed tab and Delete last 15 minutes. A tab opened by another app's link closes when Back leaves it, and you are back in that app, as in Chrome.
- **Zoom per site** — Menu → Zoom: minus, a slider and plus in 10% steps (50-300%), the page reflowing as it moves, kept for that site (`SiteZoom`, by domain without www./m.) while every other site keeps the text size from Accessibility; Reset returns it. Settings → Accessibility lists the sites with their own zoom. Not kept in Night Owl; cleared with history.
- **Quick delete** — Delete last 15 minutes (tab deck overflow, Settings → Browsing data) takes the last 15 minutes off history and home's shortcuts; cookies and cached files stay, which the row says.
- **Feel** — every bar button gives a light tick under the finger and springs as it is pressed (`Haptics`, `Motion`); the owl a firmer one. Settings → Customize → Vibration on tap turns them off, and the phone's own Touch feedback setting is honoured.
- **The owl** — says hello when the browser opens: it sleeps low in its window behind the splash, rises once the bar is on screen and the app has settled, wakes (groggily by day, at once at night), looks at you, tilts its head and winks; back after twenty minutes it opens drowsy eyes wide, after a few minutes it gives a slow blink and a nod. Its eyes hold on something and dart to the next (quick for small glances, slower with a slight settle for big ones, turned in a little when looking at you), the head follows a beat later, it blinks at uneven intervals (sometimes twice, sometimes half way), breathes in shorter than out, and now and then tilts its head at what it is looking at. Under a finger it squashes and smiles, a tap makes it hop with squash and stretch, a long press fluffs it up; while a page loads its eyes follow the ring round, and when the page is in it blinks contentedly and nods. Night Owl widens its pupils. Its springs are solved exactly per frame, so the motion is the same at 30, 60 or 120fps; it draws every frame (to 60fps) only while something moves, nothing at all under the search page or the tab deck, and holds still, looking at you, when animations are off.
- **Closed tabs come back** — a tab closed in the deck shows "Tab closed · Undo"; Menu → Reopen closed tab brings back the last ten, in their places, the newest three with their back/forward history. Never Night Owl tabs.
- **Default browser** — Settings → Make Search your default browser (Android's own role request from Android 10, Default apps before), and a one-time offer from the fourth launch on, never in the same launch as the review prompt.
- **Address bar suggestions** — besides history, bookmarks and the engine's suggestions: open tabs matching what is typed come first as "Switch to tab" (Night Owl and normal tabs are never mixed), and with the box empty a link copied in the last ten minutes is offered as "Link you copied". From Android 12 the clipboard is only read when that suggestion is picked, using the system's own note that it holds a link, so the "pasted from your clipboard" notice does not appear every time search opens.
- **Sign-in pop-ups** — "Continue with Google" style pop-ups open as a tab and return to the site when done. A pop-up that comes back from the provider and then stalls on a blank callback page, or whose `window.close()` is refused, is folded back into the tab that opened it, which is reloaded so it picks up the new session.
- **Resilience** — a crashed or reclaimed page renderer reloads the tab instead of taking the app down; a page that stops responding - which holds up every tab, since they share one renderer - gets a "wait or end it" prompt, from Android's report (Android 10+) or the app's own check that Home and New tab actually start loading; "Wait" holds it back for 10 seconds, not for good; ending it restarts the pages (Android 10+) or the browser with its tabs (older), pages that are still stuck after that are offered a restart of the browser with its tabs (`RestartActivity`), and the tab that hung - or one whose renderer died twice in 20 seconds - comes back as a "stopped" page with Try again rather than loading into the same trouble; the number of tabs kept live is sized to the phone's memory, and background tabs are frozen when Android reports memory is short. Open tabs are saved to disk (`SessionStore`) shortly after every navigation and whenever the app is left, so after a crash, a swipe from Recents or Android reclaiming the app they come back: the tab that was showing opens with its back/forward history, the others load theirs when opened. Night Owl tabs are never saved.
- **Top Stories** — world news from international, free-to-read editions (BBC News, The Guardian, NPR, Sky News, France 24, ABC News, CBS News, UN News - the "World" category, ranked first for breadth, with stories several of them run at once rising as trending) alongside a technology-and-culture feed from 22 curated publishers (The Verge, Ars Technica, WIRED, TechCrunch, TechRadar, Tom's Hardware, Android Central, 9to5Google, 9to5Mac, IGN, Eurogamer, GameSpot, NASA, ESA, Google AI, OpenAI, Variety, Pitchfork, ESPN, Condé Nast Traveler, Dezeen and more) across categories from AI and Mobile to Gaming, Space, Music, Sports, Travel and Design. One lead story leads as a large card, chosen by freshness, how many outlets carry it, source quality, image quality and category variety, so it is not always tech; the stories after it are full cards too (picture, headline, summary, site icon and a share button), every one with a picture, and "See all" opens the full list with category filters. Optional YouTube trending videos when a YouTube Data API key is configured. Stories about violence, injury, war and conflict, crime, disasters or death, and any a publisher marks as distressing, are left out, so nothing grim reaches the home page. Opens at once from the saved stories and refreshes behind them (and as the app comes to the front), swapping fresher ones in when you are at the top; persisted to disk for offline use, and refreshed when connectivity returns.
- **Tabs** — card-based tab deck with thumbnails that rises in on a spring (Bookmarks, History and Downloads open in the same deck), starting only once its list is laid out and drawn from a layer while it moves, so it opens smoothly; flick a card sideways to close its tab (a fast flick flies off, a slow drag springs back).
- **Load measurement** — every web page is timed from its own Performance timeline a moment after it finishes (`PageMetrics`): DNS, connection, TLS, time to first byte, DOMContentLoaded, load, first and largest contentful paint, long main-thread tasks, bytes transferred, scripts, images, page size and the protocol it came over. From those each page is classed light, medium or heavy. When Android reports memory getting short (but not yet low), background tabs holding heavy pages are frozen first. Measurements stay on the phone; in debug builds each page's line is in the debug log.
- **Performance & health** — Settings → Performance & health shows how Search is running on the phone, version by version (`HealthStats`): crash-free sessions, crashes, ANRs and low-memory kills (from Android's exit records on Android 11+), page-engine crashes and reclaims, stuck pages, pages loaded and failed, HTTP errors, downloads and download failures, cold and warm start-up time, average time to first byte, first and largest paint and page load, page weight counts, and memory warnings. Only counts and timings are kept, never sites, and nothing is sent anywhere or shared from the app. Ad numbers (requests, fills, errors) are shown in debug builds only.
- **Connection states** — a page slow to arrive says what it is waiting on in a small pill over the top of the page: "Connecting to example.com…", then "Waiting for example.com…", then "Loading content…" once it starts to arrive; fast loads show nothing. If the network drops part-way, the pill says "Connection lost · Retry", and the page reloads by itself when the network is back. A tab showing the offline or "can't reach" page retries on its own when the connection returns (or when it is next opened), each tab remembering the address that failed. A load cut by a Wi-Fi/mobile switch is retried once before any error page. The menu's Reload is Stop while a page is loading.
- **Pull to refresh** — pulling a web page past its top brings a refresh disc down with rubber-band resistance; past the trigger it spins and reloads. Driven by the page's own overscroll (`BrowserWebView`), so a list scrolling inside a page never triggers it.
- **Print or save as PDF** — a menu row hands the page to Android's print screen, which offers Save as PDF on every phone; the page lays itself out for paper with its own print styles.
- **Sites that ask for a password** — a page protected by HTTP sign-in (a router, a NAS, an intranet) gets a sign-in dialog instead of a blank page.
- **Menu** — opens on a spring from the Menu button, drawn from a layer while it grows, and can be dragged down to close (`DragPanel`).
- **History & Bookmarks** — with friendly empty states.
- **Permissions by site** — Settings → Site settings lists every site that has asked for the camera and microphone or for location, with the answer it got (Allowed, Blocked, Ask). Tap a site to set each to Allow, Block or Ask every time, or to forget the site; Search Security's "Reset site permissions" still forgets them all.
- **Browsing data** — Settings → Clear browsing data opens a screen listing what Search keeps on the phone with its size: cached files, cookies, site storage (local storage, IndexedDB, service workers), history, and downloads (`BrowsingData`). Each is cleared on its own, so freeing space does not have to sign you out of every site; "Clear all browsing data" is still the last row and does exactly what the old button did. Downloads are never deleted from there: the row opens the Downloads screen.
- **In-app Downloads** — view, open, and remove downloads without leaving the app. Running downloads show how much of how much and their speed ("45% · 1.8 GB of 4.0 GB · 12 MB/s"). Web downloads go to Android's DownloadManager, which fetches them in its own process (multi-GB files, any network, resuming after a drop); if it refuses one (it can be switched off on a phone) the app streams the file itself (`HttpSave`). Files a page hands over itself (blob: and data: links - exports from web apps) are streamed to Downloads in 2MB pieces (`DownloadSink`, `blobFileChunk`) with a progress notification, so their size is no longer capped (it was 16MB, held whole in memory). Before a download starts, its size is checked against the free space: a file that would leave under 200MB is stopped with a "Not enough storage" message and a shortcut to storage settings; one that would take half the free space or leave under 1GB is confirmed with a warning, even when download confirmation is off. The confirmation shows the size, where it goes and the space free. A failed download reads "Failed · tap to retry" and is fetched again from its address, with the site's cookies and the same space check; a paused one says what it is waiting for (network, Wi-Fi, a retry) and DownloadManager resumes it by itself.
- **Ad blocking** — built-in, for ads on websites (off by default; the app's own AdMob card is not affected). Per-site exceptions (`AdBlockSites`): while blocking is on, the menu offers "Allow ads on this site" / "Block ads on this site" for the site on screen, judged by the page's site so everything that page loads is let through; Settings → Ad blocking lists the allowed sites, each removable.
- **Night Owl** — private browsing mode with a dedicated empty state.
- **Multiple search engines** — Google, DuckDuckGo, Bing, Yahoo, Ecosia, Brave, Startpage, Yandex (with icons).
- **Media controls** — background media detection and playback controls.
- **Games** — a one-time welcome, then opens the web games section.
- **Browsing experience: Explore, Focus, Zen** — three ways to have the home page over one browser (`BrowsingMode`, one stored value, anything else reads as Explore). **Explore** is the home page exactly as it was: search, shortcuts, Jump back in, Top Stories and the feed ad. **Focus**: the search box, one row of shortcuts and Jump back in, placed just above the middle of the screen; no news is requested and no feed ad. **Zen**: the search box alone, larger and centred under the wordmark (Settings can add four shortcuts under it); nothing optional is drawn or fetched. Tabs, bookmarks, history, downloads, privacy and security are the same in all three, and changing mode clears and closes nothing. Changed in Settings → Appearance & browsing → Browsing experience (applies at once, the home page recomposing without a reload). A fresh install gets the owl's introduction (`ModeIntroActivity`: the owl arrives and says hello, the three modes side by side with previews, Skip keeps Explore); people upgrading stay on Explore and are told once: "Search has 3 modes now". The app open ad shows in every mode.
- **Top Stories card** — after Chrome's Discover: the whole feed is one white card (24px corners, a hairline) on the page's grey, and the stories run down it, each with its picture the card's full width, the headline in a calm medium weight, and a publisher row - round icon, name (a YouTube video's channel, then "YouTube"), age, Share and a ⋮ menu (Open in new tab, Open in Night Owl tab, Copy link, Share, Not interested in this story, Hide stories from the publisher, with Undo; kept on the phone in `FeedHidden`, cleared with history). The featured story leads the card with a taller picture, a "Top story" tag, a bigger headline and its summary; videos carry a play button.
- **Ads and consent** — one native AdMob card in the home feed, drawn as one more story on the story card (full-width media, the headline in the stories' type, the advertiser's icon, an "Ad" label and the call to action in the accent), placed after the second story under the featured one: home.html keeps an empty box of the card's height there and reports where it is (`SearchApp.adSlotAt`), and the native card is laid over it as the page scrolls (`positionAdSlot`), fading in once the box has opened; with fewer stories it follows the last one, with no stories it sits at the end of the page. An app open ad (`AppOpenAds`, unit 3558362744) is what the browser opens through: splash, ad, home. On a launch the splash stays up until the ad has loaded and the ad is shown over it; coming back from the background the splash's picture goes up over the browser and the ad is shown over that; closing the ad uncovers home. Nothing waits on a clock - only a failed request lets the browser open without the ad (and a long guard for a request that never answers, which still keeps its ad for the next open). Never shown over home once it is up; not for a link, text or shortcut the browser was opened for, not on coming back from somewhere the browser sent you (share sheet, file picker, another app, the ad's own click), never in Night Owl, for supporters or without consent, and not on the first launch (consent and the owl's introduction); used within four hours, retried like the feed ad. Neither ad is ever over a site. At launch Google's User Messaging Platform (`AdConsent.kt`) shows the AdMob privacy message wherever one applies (GDPR for the EEA, UK and Switzerland; the US states message), and no ad is requested until it says ads may be. Users in those regions get Settings → Ad privacy choices, Google's form to change or withdraw consent or opt out of sale or sharing; everyone else never sees the row. Debug builds request Google's native test unit, never the live one. A request that comes back empty is asked again after 30 s, 2, 5 and 15 minutes, again when the network returns and when the app comes back to the front, and a card over an hour old is replaced (AdMob counts it as expired); an invalid request (code 1) or a missing app ID (8) is not retried. In debug builds, Settings → Performance & health → Ads shows how many were asked for, filled, failed and seen, the last error code with what it means, the last reason none was asked for (consent, Night Owl, supporter), and consent failures; release builds show no ad numbers.
- **Support/Plus** — in-app purchase to support development (Play Billing).
- **In-app updates** — via Play App Update.
- **Settings** — grouped, card-based, every screen alike: the sections (Security, Ad blocking, Site settings, Accessibility, Customize, Browsing data, Performance & health) are built of the same labelled cards as Settings itself, on the same neutral page colour as every other screen (Settings had a lavender page of its own). Switches, radio buttons, dialog buttons, icons and labels all take the accent picked in Customize (`ThemeOverlay.Search.Accent.*`, `Settings.applyAccent`). New: Search suggestions (Security; off keeps what is typed on the phone), Dark websites (Customize, Android 13+, dark theme), Force enable zoom (Accessibility), Vibration on tap and Open home after 4 hours away (Customize), Add the Search widget, Delete last 15 minutes (Browsing data), blocked counts (Ad blocking).

## Tech stack

- **Language:** Kotlin
- **UI:** Android Views + XML layouts (native shell) + HTML/CSS/JS (`home.html`)
- **Rendering:** Android WebView (`androidx.webkit`)
- **Build:** Gradle (Kotlin DSL), AGP, R8 minification for release
- **Key libraries:** AppCompat, Material, ConstraintLayout, RecyclerView, Activity-KTX 1.10.1, Play Billing 8.0.0, Play App Update 2.1.0, Google Mobile Ads 25.4.0, User Messaging Platform 3.1.0, Play Services Code Scanner (QR), Media, Core Splashscreen.

## Design tokens

`res/values/dimens.xml` is the single source of truth for spacing (4dp grid), corner radius, text sizes, and icon sizes. New UI should reference these tokens (`@dimen/space_md`, `@dimen/radius_lg`, `@dimen/text_body_lg`) instead of hard-coded values.

## Permissions

- `INTERNET`, `ACCESS_NETWORK_STATE` — browsing + connectivity detection
- `POST_NOTIFICATIONS` — download/update notifications
- `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK` — media controls
- `WRITE_EXTERNAL_STORAGE` (legacy, capped) — downloads

## Building

### In GitHub Codespaces (recommended)
The repo includes a devcontainer that provisions JDK 17 and the Android SDK. Open in a **full Codespace** (github.com → Code → Codespaces) — the browser-based github.dev editor cannot build. The devcontainer runs `.devcontainer/setup-android.sh`.

### Build commands
./gradlew assembleDebug # Debug APK
./gradlew assembleRelease # Release APK (R8 minified) — smoke test
./gradlew bundleRelease # Release AAB for Play
### Release signing
Release builds are signed via a git-ignored `keystore.properties` + `search-release.keystore` (alias `search`). Not in the repo (`.gitignore` covers `*.jks`, `*.keystore`, `keystore.properties`, `local.properties`).

## Release / distribution

- Distributed via **Google Play** (production).
- Each Play upload needs a unique, incrementing `versionCode`.
- Release notes and Data Safety declaration must stay consistent with actual behavior.
